# Decision Protocol

**Status:** Proposed reference protocol

The purpose is to produce better decisions without confusing AI consensus with authority.

---

## 1. Classify the Decision

Record:

- objective
- owner
- decision class
- deadline
- reversibility
- maximum loss / impact
- required human authority
- required evidence standard

---

## 2. Decompose

Separate the problem into material subquestions.

Do not create more branches than can change the decision.

Examples:

- factual state
- causal drivers
- options
- downside
- timing
- legal constraints
- financial impact
- second-order effects

---

## 3. Independent First Pass

For consequential decisions, selected agents should analyze independently before seeing other agents' conclusions.

This reduces premature convergence.

Outputs should include:

- conclusion
- evidence
- uncertainty
- strongest counterargument
- what would change the conclusion

---

## 4. Adversarial Review

Assign explicit critics to:

- falsify key claims
- search for missing evidence
- expose correlated assumptions
- test downside scenarios
- identify authority / ethics conflicts
- detect prompt or source manipulation

---

## 5. Cross-Evaluation

Agents can evaluate other outputs, but the system should preserve:

- minority views
- unresolved contradictions
- unique evidence
- uncertainty

Do not reduce all disagreement to a numerical average.

---

## 6. Synthesis

The synthesis package should contain:

- facts
- inferences
- options
- expected benefits
- downside
- assumptions
- unresolved unknowns
- dissent
- recommendation
- confidence
- decision sensitivity

---

## 7. Human Decision

The designated human authority can:

- approve
- reject
- modify
- request more evidence
- defer
- delegate a bounded subdecision

The reason can be recorded without requiring performative justification for every low-risk choice.

---

## 8. Pre-Execution Gate

Before an external side effect:

- verify the authorization
- verify policy version
- verify scope
- verify target
- verify amount / parameters
- verify required co-approval
- apply cooling-off if required
- confirm execution channel

---

## 9. Execute

Execution receives only the minimum permissions required.

Do not give the analysis system unrestricted standing authority merely for convenience.

---

## 10. Verify Outcome

Check:

- did the intended action occur?
- did anything else occur?
- did constraints hold?
- is rollback required?
- did new evidence invalidate the decision?

---

## 11. Record and Learn

Persist:

- decision package
- authorization
- execution record
- result
- later outcome
- correction if needed

Learning updates future decisions without rewriting history.

---

# Escalation Rule

Escalate rather than synthesize away disagreement when:

- evidence is contradictory
- downside is asymmetric
- action is hard to reverse
- one agent finds a unique severe risk
- authority is disputed
- legal / fiduciary duty may be affected
- confidence is high but evidence provenance is weak

---

# Stop Rule

More agents, more debate and more research are justified only when they can materially improve:

- decision quality
- risk detection
- calibration
- reversibility
- authority integrity

Otherwise stop.
